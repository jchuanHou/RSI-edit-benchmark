# Text2Earth_edit：分支概览与研究总结

> 分析日期：2026-10-07。
> 完整本地仓库：`/data/workspace/Text2Earth_edit_full`。已通过 Git 对象完整性检查，包含全部 15 个远端实际分支及 120 个历史提交，不是浅克隆或部分克隆。
> 本文依据已提交的代码、配置、提交历史和实验归档整理；没有重新运行模型。没有提交到仓库的实验，不在本次判断范围内。`origin/HEAD` 是默认分支的别名，不另算一个分支。

## 一、先看全貌

你的项目不是单独的一条算法路线，而是围绕 **Text2Earth-Inpainting 的免训练遥感编辑**，同时推进了四类工作：

1. **数据与实验基础设施**：基于 RSICD 构建编辑数据、制作 mask/prompt、批量生成和评测归档。
2. **免训练算法探索**：初始噪声优化（PriNO）、频域调节（FDGM）、奖励梯度引导（DeGu）、边界一致性（BA/BC-PriNO）。
3. **基线与方法校准**：SD1.5 Inpainting 对比、InstructPix2Pix 准备，以及更忠实的 FreeInpaint PriNo 适配。
4. **模块融合**：先融合 FDGM 与 DeGu，再融合 PriNO、FDGM、DeGu 三个模块。

**重要区别：`main` 仍是上游 Text2Earth 的旧版本，不代表你的研究进度；最新研究代码在 `feat/tri-unified`，但最新代码不等于已有最充分实验验证的版本。**

## 二、每个分支是干什么的

### A. 原始基线与早期集成

| 分支 | 大概用途 | 当前进度与阅读建议 |
|---|---|---|
| `main` | 保留原始 Text2Earth 项目，包含文生图、局部重绘及分辨率条件能力。 | 是对照起点，不是你自己的方法集成分支。HEAD 为 `da7ae77`，日期为 2025-09-18。 |
| `dev/unified-pipeline` | 早期统一算法入口，把 PriNO、FDGM、DeGu 等处理环节放进一套可组合的推理流程。 | 主要用于算法集成与试验，后来把评测工具拆到了其他分支。适合回顾最初的整体设计，不能直接把它理解为最终最优方案。 |
| `experiments/full-ablation-v1` | 早期完整实验与消融归档：原始基线、FDGM、PriNO、BA-PriNO、FDGM＋PriNO，以及后续 SD1.5 对照。 | 有多组全量实验记录，是回顾早期结果最重要的分支。但不是所有记录都完整，也不是包含三模块全部组合的完整消融；其中有一次只生成 359 张的中断实验。 |

### B. 单方向算法探索

| 分支 | 大概用途 | 当前进度与阅读建议 |
|---|---|---|
| `feat/rs-prino` | 将 FreeInpaint 的 PriNO 思路适配到 Text2Earth：在正式生成前优化初始噪声，使注意力更集中于编辑区域；同时保留 BA-PriNO 的边界注意力变体。 | 已有实现，相关全量结果主要在早期消融分支。它是免训练适配，但需要推理时梯度优化，不能等同于低计算成本。 |
| `feat/rs-degu` | 早期 DeGu 适配：在去噪过程中，通过文本或协调性奖励对 latent 求梯度，调整生成方向。 | 管线已实现，但没有找到该路线完成全量验证的归档。示例中的奖励挂载和权重配置还存在需要核对的地方。不要和后来的 RSCLIP DeGu 分支混为一谈。 |
| `feat/fdgm` | 频域引导路线：从直接处理噪声预测，逐步演进到处理预测图像 latent，再到使用原图频谱作为参考的匹配。 | 有多代实现及多组实验。早期 v2/v3 的已测试配置总体退化；v4 转向 SAM，即 **Spectrum-Aligned Matching（频谱对齐匹配）**，不是 Segment Anything。该分支自身没有 v4 完整结果归档，后续融合链中可见相关实验材料。 |
| `feat/bc-prino` | 把初始噪声优化的重点改为边界协调：尝试梯度、频谱、统计量等约束，形成 A1–A5 五种方案。 | A1–A5 均有实现，但只有 baseline、A1、A2 有归档结果；还增加了边界专项评测。已记录提升很小，计算成本明显增加，不能把 A3–A5 写成已验证成功。 |
| `feat/degu-text-rsclip` | 使用冻结的 Git-RSCLIP 作为遥感语义奖励，对去噪过程做免训练梯度引导；探索全图奖励、背景复合、引导时段及局部区域等变体。 | 实现了 S1–S5 和 v2A/v2B。S1、S2、S4 有结果，S3、S5 未见结果；v2A/v2B 的结果后来归档在融合分支。v2 是更值得保留的可控引导起点：增加 mask 梯度门控、引导时间窗和梯度强度归一化。 |

### C. 复现校准与后期融合

| 分支 | 大概用途 | 当前进度与阅读建议 |
|---|---|---|

## 三、这些分支之间是什么关系

可以把研究过程记成下面几条线：

- **早期探索线**：PriNO／BA-PriNO、FDGM、DeGu → `dev/unified-pipeline` 集成 → `experiments/full-ablation-v1` 做集中实验。
- **初始噪声线**：`feat/rs-prino` → `feat/freeinpaint-prino-faithful`；另有 `feat/bc-prino` 探索边界损失。
- **频域线**：`feat/fdgm` 持续改进 v1–v4，后续把频谱匹配思路带入融合实现。
- **近期集成线**：`feat/degu-text-rsclip` → `feat/fdgm-degu-fusion` → `feat/tri-unified`。
- **支撑线**：`infra/dataset-tools` 和 `infra/eval-pipeline` 负责数据与评测，两个 `repro/*` 分支负责通用模型对照。

这里前几条是研究内容的演进概括，不都代表直接 Git 继承。可确认的直接关系是：**RSCLIP DeGu → 双模块融合 → 三模块融合**；faithful 分支从 RS-PriNO 发展而来。RSCLIP DeGu 不是旧 `feat/rs-degu` 的直接后代；三模块分支复制了 faithful 管线文件，不等于完整合并了 faithful 分支。

## 四、当前研究内容和进度总结

### 1. 已经完成了什么

- 已搭建一个从数据组织、mask/prompt 标注到批量生成、评测归档的研究框架。
- 已将研究重点覆盖到生成的三个阶段：**初始噪声、去噪过程、边界及频域约束**。
- 已完成多条算法管线和多组 1550 张级别的全量实验，不再是停留在构想阶段。
- 已开始检查早期方法复现是否忠实，补充局部语义和边界指标，并尝试融合模块。

因此，更准确的阶段定位是：

> **已经完成较充分的工程实现和探索性实验，现在需要收敛研究问题、校正评测协议，并验证哪些提升真正可靠。**

### 2. 尚未完成什么

- 尚未证明存在一个在语义正确性、区域保真、边界质量和成本之间均有稳定优势的最终方法。
- 三模块集成尚无入库结果；部分分支的多个变体只有实现或配置，未形成对应实验结论。
- 没有完成统一协议下的全套单模块/组合消融、多随机种子验证。
- 数据集仍缺明确的研究用开发集/测试集区分、编辑任务标签、审核记录及完整资产版本绑定。

### 3. 目前实验透露的信号

| 路线 | 当前证据说明什么 |
|---|---|
| 早期 PriNO／BA-PriNO | 在同一早期评测表中，CLIP 从约 27.710 增至约 27.747，但耗时从约 3345 秒增至约 3.7 万秒，约为 11 倍。现有微小指标变化不足以证明实用净收益。 |
| FDGM v2/v3 | 已测配置的 FID、CLIP，或补评的 FWD 总体变差，不支持继续盲目加强滤频或扩大扫参。也不能据此否定后续参考频谱匹配这一不同设计。 |
| BC-PriNO | A1/A2 的整体与边界指标变化很小，但耗时约为基线的 1.9 倍和 3 倍，尚缺可重复、可解释的收益。 |
| RSCLIP DeGu | 已有语义奖励与局部控制的实现和结果，但不同实验使用的 CLIP 编码器及口径不一致，不能直接根据表面分数宣称优于基线。 |
| FDGM＋DeGu | F1 已跑完，但缺少同口径单模块对照，暂不能证明融合优于各自单独使用。 |
| faithful PriNo／三模块方案 | faithful 提供了更可靠的复现对照；三模块目前主要是工程整合，仍待实验验证。 |

这些数字是仓库归档记录，不是本次重跑结果；耗时比较还受实际硬件、运行配置和续跑状态影响。

## 五、需要优先处理的几个问题

### 1. 数据清单与实际 prompt 条目需要统一

`dataset_info.json` 中 1550 张均来自 RSICD train，但 `prompts.json` 中对应为 1543 张 train 加 7 张 test。这里首先说明的是**清单不一致**，不能直接推断你训练了模型或发生了训练泄漏。

自动标注工具使用随机形状 mask 和类别文本模板，Web 工具允许人工调整。仅凭最终 JSON，无法判断每张样本是否经过人工审核，也无法保证文本目标与 mask 实际覆盖区域一致。建议将这一点作为数据集质量检查，而不是直接把全部样本称为人工标注编辑基准。

### 2. “像原图”不能替代“编辑正确”

目前不少指标以编辑前原图作为 reference。对于恢复型补全可以理解，但对于“建筑替换为绿地”这类任务，正确编辑本来就应改变原图。

因此，低 FID 或低全图 LPIPS 不能单独证明编辑成功；反过来，FID 变差也不能单独证明方法失败。需要同时检查目标类别/属性是否生成、旧对象是否消失，以及非编辑区是否保持。

### 3. 评测口径还不统一

- 早期区域 LPIPS 没有开启空间输出，却尝试按 mask 统计，得到异常的 inside/outside 样本分配；这部分不能作为区域保真证据。
- 不同归档混用了 OpenAI CLIP B/32、L/14 等编码器，27 分与 22 分不能直接比较高低。
- 后来的 Local CLIP 是 mask 外置黑后的整图评分，不等同于局部 bbox 裁剪评分；全图 LPIPS 也不等于背景 LPIPS。
- 统一管线与独立管线的原图 latent 回填处理不同，消融中可能混入了不止一个因素。
- 不同 runner 的随机数使用和续跑处理不同，“seed 都写 42”并不意味着逐图使用了同一份噪声。

这些问题不会抹掉你的已有工作，但会削弱论文中“某模块带来了提升”的因果论证。

## 六、当前方向是否值得继续

**结论：值得继续，但应从“不断增加模块”转为“修正评价、筛选有效机制、收敛一个问题”。**

| 处理建议 | 对应内容 | 原因 |
|---|---|---|
| **保留并优先完善** | 数据集工具、评测框架、完整实验归档 | 这些是已经形成的积累，也决定后续结论是否可信。 |
| **保留为校准基线** | 原始 Text2Earth、SD1.5、faithful PriNo | 用来区分遥感底模、免训练适配与新增模块各自的贡献。 |
| **继续做小规模、有假设的验证** | RSCLIP DeGu-v2、FDGM-SAM | 局部梯度控制和参考频谱匹配比早期全局强引导/强滤频更值得进一步验证，但现有证据还不支持宣布成功。 |
| **暂缓扩大投入** | 旧版强滤频、大规模 BA/BC 参数扫描 | 归档收益弱或退化，且部分方法额外成本很高；应先明确具体失败样本和机制假设。 |
| **先验证再整合** | 双模块、三模块融合 | 模块多不等于贡献强。先证明单模块解决了不同问题，再讨论互补性。 |
| **作为补充而非三输入主基线** | InstructPix2Pix | 原生输入设定不同，当前复现也尚未完成。 |

### 推荐的下一步重点

1. **先确定一个主问题。**例如“语义修改时尽量保护非编辑区”，或“在保证语义正确的同时改善边界纹理一致性”，不要同时宣称解决所有问题。
2. **先重评已有生成结果。**统一样本清单、编码器及局部/背景/边界定义，充分利用已生成图像；缺失原始输出时再补跑。
3. **再做少量配对消融。**固定底模、回填方式、逐图噪声和后处理，从 baseline、单模块到必要组合，并报告计算成本。
4. **最后决定最终方案。**如果局部语义确有稳定收益且背景损伤受控，就围绕局部引导收敛；如果频谱匹配能在特定编辑任务中稳定改善边界，再作为互补模块，而不是默认与所有任务绑定。

### 一句话总结

> 你已经有一套比较完整的遥感编辑研究原型和不少全量实验；当前最缺的不是新分支，而是把数据与评测对齐，确认少数真正有效的模块，再将其组织成一条能被清楚证明的研究主线。
