## 1. 问题清单

严重程度：🔴 会导致报错或错误结果 / 🟠 隐患或会误导使用者 / 🟡 代码质量或文档问题

### 1.1 Pipeline 相关

| # | 级别 | 位置 | 问题 | 触发条件 / 影响 | 修复建议 |
|---|:---:|---|---|---|---|
| P1 | 🔴 | 三个 pipeline 的 `res` 解析段 | `res` 只在 `prompt` 为 str 或 list 时赋值 | 只传 `prompt_embeds`、不传 `prompt` 时，去噪循环中引用 `res` 会抛出 `UnboundLocalError` | 在解析前加 `res = [0] * batch_size` 作为默认值，或新增显式参数 `resolution_level` |
| P2 | 🔴 | 去噪循环 `assert num_images_per_prompt == 1` | 每个提示词只能生成一张图 | 传 `num_images_per_prompt > 1` 直接触发 AssertionError | `res = res.repeat_interleave(num_images_per_prompt)`，`res_null` 同步扩展，然后删除 assert |
| P3 | 🔴 | 前缀解析 `int(prompt.split(...)[0])` | 没有容错和范围检查 | 前缀不是整数（如 `"2m_GOOGLE_LEVEL_..."`）会抛出 ValueError；超出 10 ~ 18 的值会静默外推 | 加正则校验，并对超出训练范围的值给出警告 |
| P4 | 🟠 | `height`/`width` 默认值 | 默认 `sample_size × 8 = 512` | 不传尺寸时生成 512×512，属于训练分布外（模型在 256 上训练），质量可能下降 | 调用时总是传 `height=256, width=256`，或修改默认值 |
| P5 | 🟠 | 文生图 pipeline 的 `guidance_scale` | 默认值仍为 7.5 | 不传参数时引导过强（论文最优约为 3 ~ 4），容易过饱和 | 显式传 3.5，或把默认值改为 3.5（与重绘 pipeline 一致） |
| P6 | 🟡 | 循环内 `res = torch.tensor(res, ...)` | 每一步都重新构造张量 | 第 2 步起 `res` 已是张量，会触发 PyTorch 的 “To copy construct from a tensor...” UserWarning；也有无谓的开销 | 把张量构造移到循环之前 |
| P7 | 🟡 | 调度器配置 | `model_index.json` 声明 `PNDMScheduler`，`scheduler_config.json` 的 `_class_name` 是 `DDIMScheduler` | README 注释称默认使用 DDIM，实际加载的是 PNDM，容易让人困惑 | 按 README 的做法显式指定调度器 |
| P8 | 🟡 | 三个 pipeline | 解析逻辑复制了三份，并留有 `# FIXME`、`# fixme`、`# TODO` 和大段注释掉的调试代码 | 维护困难 | 抽成公共函数并清理 |

### 1.2 ControlNet 改动

| # | 级别 | 问题 | 影响 |
|---|:---:|---|---|
| C1 | 🟠 | 就地修改了官方 `StableDiffusionControlNetPipeline` | 安装本仓库后，**所有使用该类的代码**都会继承 P1、P2、P3 的问题；提示词中的 `_GOOGLE_LEVEL_` 也会被解析 |

## 2. 安全提示汇总

| 风险点 | 说明 | 建议 |
|---|---|---|
| `custom_pipeline` + Hub 脚本 | Usage 1 会从 HF 下载并执行 `pipeline_text2earth_diffusion.py` | 已核实当前 Hub 版本与本仓库逻辑一致；生产环境应改用本地类，或固定 Hub 的 `revision` |
| `trust_remote_code=True` | 允许执行远程代码 | 使用本地类时删除该参数 |
| `torch.load` 加载 `.pth` | pickle 反序列化可执行任意代码 | 使用 `weights_only=True` |
| 模型权重格式 | HF 上的主模型权重是 `safetensors`，不涉及 pickle | 安全 |
| `safety_checker=None` | 关闭了 NSFW 检测 | 遥感场景下影响不大；如果对外提供服务，需要自行评估生成内容的合规性 |

## 3. 在本服务器上的部署建议

### 3.1 环境匹配度

| 项目 | 本机情况 | 需求 | 结论 |
|---|---|---|---|
| GPU | Tesla T4，15 GB 显存 | FP16 推理 | ✔ |
| 精度 | T4 支持 FP16 Tensor Core，不支持 BF16 加速 | README 示例使用 FP16 | ✔ |
| 驱动 | 535.161.07（最高支持 CUDA 12.2） | PyTorch 选 cu121 或 cu118 | ✔ |
| Python | 系统自带 3.9.16，没有 conda | README 推荐 3.9 | ✔（用 `venv` 代替 conda） |
| 磁盘 | `/data` 剩余约 491 GB | 两个模型约 6.9 GB | ✔ |
| 网络 | 已验证可以访问 huggingface.co | 下载权重 | ✔（慢的话可改用 ModelScope） |

### 3.2 显存估算（推测，未实测）

| 项 | FP16 大小 |
|---|---:|
| UNet 权重 | ~1.74 GB |
| 文本编码器权重（以 FP16 加载） | ~0.68 GB |
| VAE 权重 | ~0.17 GB |
| 256×256、CFG 批次为 2 时的激活 | 远小于 1 GB |
| **合计** | **约 3 GB**，T4 足够；批量生成或 512 分辨率也有较大余量 |

### 3.3 推荐步骤

```bash
# 1. 独立虚拟环境（避免覆盖系统的 diffusers）
python3 -m venv /data/venvs/text2earth
source /data/venvs/text2earth/bin/activate
pip install -U pip

# 2. PyTorch（CUDA 12.1 构建，兼容 535 驱动）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 3. 依赖与本仓库
pip install "transformers>=4.25.1" accelerate safetensors
cd /data/workspace/Text2Earth && pip install -e .

# 4. 把 HF 缓存放在大容量盘
export HF_HOME=/data/hf_cache
```

```python
# 5. 最小验证脚本
import torch
from diffusers import Text2EarthDiffusionPipeline, EulerDiscreteScheduler

mid = "lcybuaa/Text2Earth"
pipe = Text2EarthDiffusionPipeline.from_pretrained(
    mid, torch_dtype=torch.float16, safety_checker=None,
    scheduler=EulerDiscreteScheduler.from_pretrained(mid, subfolder="scheduler"),
).to("cuda")

g = torch.Generator("cuda").manual_seed(0)
img = pipe("16_GOOGLE_LEVEL_Seven green circular farmlands are neatly arranged on the ground",
           height=256, width=256, num_inference_steps=50, guidance_scale=3.5, generator=g).images[0]
img.save("/data/workspace/circular.png")
```

如果安装后遇到 `huggingface_hub` 的 API 兼容问题（例如新版本移除了 `cached_download`），可以把 `huggingface_hub` 降到 0.23 ~ 0.25 之间。

## 4. 二次开发建议

| 目标 | 建议做法 |
|---|---|
| **修复 P1/P2/P3** | 在 `__call__` 中新增 `resolution_level: Optional[Union[int, List[int]]] = None` 参数，优先级高于提示词前缀；`res` 默认为 0；按 `num_images_per_prompt` 用 `repeat_interleave` 扩展；把张量构造移到循环外 |
| **分离引导** | 利用 DCA 训练出的 \(\epsilon(\tau,\varnothing)\) 能力实现双系数引导（每步 3 次 UNet 前向）：\(\epsilon=\epsilon_{\varnothing\varnothing}+s_\tau(\epsilon_{\tau\varnothing}-\epsilon_{\varnothing\varnothing})+s_\rho(\epsilon_{\tau\rho}-\epsilon_{\tau\varnothing})\)，单独调节分辨率依从强度 |
| **无界外扩** | 基于 `Text2EarthDiffusionInpaintPipeline` 实现滑窗外扩：固定 Level，窗口 256，重叠 64 ~ 128 px，用软掩码羽化接缝；或者用 MultiDiffusion 在潜空间做全局一致的大图生成 |
| **复现训练** | 以 diffusers 的 `examples/text_to_image/train_text_to_image.py` 为基础：UNet 用 SD2-base 初始化并设置 `class_embed_type="timestep"`（新增的 `class_embedding` 随机初始化或零初始化）；在 collate 时以概率 \(p_1\) 把文本置空、以概率 \(p_2\) 把 Level 置 0；`class_labels=level` 传给 UNet |
| **LoRA 适配** | diffusers 原生支持 `pipe.load_lora_weights(...)`；用 `train_text_to_image_lora.py` 训练时同样需要传入 `class_labels` |
| **升级 diffusers** | 两个 pipeline 改动很小，可以移植到最新版 diffusers 的 `StableDiffusionPipeline` 子类中，以 `custom_pipeline` 形式维护，**避免 fork 整个 diffusers** |
